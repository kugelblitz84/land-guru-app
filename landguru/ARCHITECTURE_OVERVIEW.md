# Influencer App Architecture Overview

## 1. Overall Architecture Pattern: Feature-First Modular Architecture with GetX

The project follows a **feature-first modular architecture** where code is organized by features/modules rather than by technical layers. This is combined with the **MVC pattern** (Model-View-Controller) using GetX.

```
lib/
├── main.dart                 # App entry point
├── core/                     # Shared/reusable code across all modules
│   ├── controllers/          # Global controllers (e.g., LanguageController)
│   ├── enums/                # App-wide enums (e.g., AccountType)
│   ├── localization/         # Translations (i18n)
│   ├── models/               # Shared data models
│   ├── services/             # Global services (e.g., AccountTypeService)
│   ├── theme/                # App theme & color palette
│   ├── utils/                # Utility functions & constants
│   └── widgets/              # Reusable UI components
├── modules/                  # Feature modules
│   ├── auth/                 # Authentication flows
│   ├── brand/                # Brand-specific features
│   ├── influencer/           # Influencer-specific features
│   ├── ad_agency/            # Agency-specific features
│   ├── shared/               # Shared features across user types
│   └── widgets/              # Module-specific widgets
└── routes/                   # Navigation configuration
    ├── app_routes.dart       # Route name constants
    └── app_pages.dart        # GetPage route definitions
```

---

## 2. State Management: GetX

The project uses **GetX** (`get: ^4.7.3`) for:

- **State Management** - Using `Rx` types (`.obs`) and `Obx()` widgets
- **Dependency Injection** - Using `Get.put()`, `Get.lazyPut()`, `Get.find()`
- **Navigation** - Using `GetMaterialApp` and `Get.toNamed()`, `Get.offAllNamed()`
- **Localization** - Using `AppTranslations` extending `Translations`

**Controller Pattern Example:**
```dart
class LoginController extends GetxController {
  final RxBool isPasswordObscured = true.obs;   // Reactive state
  final RxBool isLoading = false.obs;
  
  void togglePasswordVisibility() {
    isPasswordObscured.toggle();
  }
}
```

**View Pattern Example:**
```dart
class LoginView extends GetView<LoginController> {
  @override
  Widget build(BuildContext context) {
    return Obx(() => /* reactive UI rebuild */);
  }
}
```

## 3. Navigation System

The project uses a **dual-layer navigation system**:

### A. Top-Level Navigation (GetX Named Routes)
- Defined in `routes/app_routes.dart` (route constants)
- Configured in `routes/app_pages.dart` (GetPage definitions)

```dart
// Route constants
class AppRoutes {
  static const login = '/login';
  static const bottomNav = '/bottom-nav';
  // ...
}

// Route configuration with bindings
GetPage(
  name: AppRoutes.login,
  page: () => const LoginView(),
  binding: LoginBinding(),   // Dependency injection per route
)
```

### B. Nested Navigation (Within Bottom Nav)
- Uses `Get.nestedKey(1)` for a nested Navigator inside the bottom navigation shell
- Routes generated by `bottom_nav_route_generator.dart`

```dart
// Inside BottomNavView
Navigator(
  key: Get.nestedKey(1),
  initialRoute: AppRoutes.home,
  onGenerateRoute: BottomNavRouteGenerator.generateRoute,
)

// Navigation within nested context
Get.offAllNamed(AppRoutes.home, id: 1);  // id: 1 = nested navigator
```

## 4. Dependency Injection Pattern

**Global Services** (permanent, app-wide):
```dart
void main() {
  Get.put(LanguageController(), permanent: true);
  Get.put<AccountTypeService>(AccountTypeService(), permanent: true);
}
```

**Per-Route Bindings:**
```dart
class LoginBinding extends Bindings {
  @override
  void dependencies() {
    Get.lazyPut<LoginController>(() => LoginController());
  }
}

// Or inline with BindingsBuilder
GetPage(
  binding: BindingsBuilder(() {
    Get.lazyPut<SignupInfluencerController>(() => SignupInfluencerController());
  }),
)
```

**Fenix Pattern** (auto-recreate when needed):
```dart
Get.lazyPut<HomeController>(() => HomeController(), fenix: true);
```

## 5. Business Logic Implementation

Business logic is encapsulated in **Controllers** (GetxController):

| Layer | Responsibility |
|-------|----------------|
| **View** (`*_view.dart`) | UI rendering, uses `GetView<Controller>` |
| **Controller** (`*_controller.dart`) | Business logic, state, API calls |
| **Service** (`*_service.dart`) | Shared business logic across features |
| **Model** (`*.dart` in models) | Data structures |

**Example Flow:**
```
LoginView → LoginController → AccountTypeService → Navigate to BottomNav
```

**Role-Based Logic:**
The `AccountTypeService` manages user roles globally:
```dart
class AccountTypeService extends GetxService {
  final Rxn<AccountType> _currentType = Rxn<AccountType>();
  
  bool get isBrand => _currentType.value == AccountType.brand;
  bool get isInfluencer => _currentType.value == AccountType.influencer;
  bool get isAdAgency => _currentType.value == AccountType.adAgency;
  
  void setRole(AccountType? type) => _currentType.value = type;
}
```

Views adapt based on user type:
```dart
if (accountTypeService.isBrand) {
  // Show brand-specific UI
} else {
  // Show influencer/agency UI
}
```

## 7. Module Structure Pattern

Each feature module follows this structure:
```
modules/auth/login/
├── login_controller.dart     # Business logic + state
├── login_view.dart           # UI (extends GetView<LoginController>)
└── (optional) login_binding.dart  # Often inside controller file
```

For complex features:
```
modules/shared/bottom_navbar/
├── bottom_nav_controller.dart
├── bottom_nav_view.dart
└── utils/
    └── bottom_nav_route_generator.dart
```

---

## 8. Localization Pattern

Uses GetX translations with `.tr` extension:
```dart
// Definition in app_translations.dart
'en_US': {
  'login_title': 'Login',
  'login_subtitle': 'Good to see you back!',
},
'bn_BD': {
  'login_title': 'লগইন',
  // ...
}

// Usage in views
Text('login_title'.tr)
```

---

## Summary Table

| Aspect | Implementation |
|--------|----------------|
| **Architecture** | Feature-First Modular + MVC |
| **State Management** | GetX (Rx observables + Obx) |
| **Navigation** | GetX named routes + nested navigator |
| **DI** | GetX (`Get.put`, `Get.lazyPut`, Bindings) |
| **Localization** | GetX Translations |
| **Theming** | Centralized `AppTheme` + `AppPalette` |
| **Responsive** | flutter_screenutil |

This architecture is highly scalable, supports multiple user roles (Brand, Influencer, Agency), and maintains clear separation of concerns.
